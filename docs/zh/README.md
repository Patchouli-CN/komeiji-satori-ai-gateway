# KomeijiSatori · 古明地覚

> 觉之瞳 —— 看穿 AI 中转商掺水的读心网关。

[English](../../README.md) · [快速上手](QUICKSTART.md) · [运维手册](HANDBOOK.md) · [安全手册](SECURITY.md) · [常见问题](QA.md)

## 这是什么

一个架在你和 AI 上游之间的网关。客户端把它当普通的 OpenAI / Anthropic 端点用，它在背后持续回答一个问题：**上游端上来的，还是当初那个模型吗？**

为什么会有这东西：中转 API 这个市场，买家手里只有一个 `model` 字段，而这个字段不值钱。卖你 Opus 实际套壳小模型的、高峰期限流时把你偷偷路由到弱模型的、同名模型几个月里悄悄降智的——全都有实拍。厂商掌握一切数据，你掌握的只有账单。觉大人做的事很简单：她不问你付了钱买的是什么，她自己看。

## 她怎么看

转发是透明的：按 `model` 路由到配置的上游，响应原样回来。检测挂在转发链路和后台核验循环上，互不挡路。

```
客户端 ──▶ 协议适配器 ──▶ 内部规范(OpenAI Chat) ──▶ 检测核心 ──▶ 上游管线 ──▶ 上游
  /v1/chat/completions        所有检测都只认规范格式，    规则·侧信道·账本
  /v1/messages                客户端说什么协议无所谓      指纹·测试·Slop
  /v1/responses
```

每个通道假设的配合度不同。厂商掐掉任何一个字段，都只是让她半闭眼，不是失明——字段可以掐，行为掐不掉：

| 通道 | 需要上游配合什么 | 抓什么 |
|---|---|---|
| 声纹指纹 fingerprint | 返回 logprobs | 掉包。首 token 的 top-logprobs 分布是权重和分词器的物理指纹，蒸馏偷得走人设偷不走分布（脳符「ブレインフィンガープリント」） |
| 答案指纹 answerprint | 什么都不需要 | 掉包+降智。固定题组 temp=0 作答，跟参考算相似度，纯黑盒——Claude 系（没有 logprobs）的主力通道 |
| 身份探针 identity | 什么都不需要 | 厂商自报矛盾、知识截止年漂移。多语言多格式题组随机抽样 |
| 金丝雀 canary | 什么都不需要 | 降智。有标准答案的题，通过率就是质量 |
| 规则引擎 rules | 什么都不需要 | 伪装提示词泄漏、厂商自报、CoT 语言穿帮、口癖。17 条内置 + 你自己的 rules.toml |
| 三条自基线侧信道 | 不伪造 usage | 分词比例、首字节延迟、计费一致性的 EMA 漂移。零额外请求，无公开特征可规避 |
| 命中率通道 | 什么都不需要 | "90% 真 10% 假"式掺水。严重规则命中率持续超阈值才告警 |
| 业务测试裁决 testing | 什么都不需要 | 你自己测试套件的通过率。降级必然导致能力下降，套件连败是供应商伪造不了的实锤 |
| 工具链审计 slop | 什么都不需要 | 工具调用参数 JSON 断裂、幻觉工具、复读、膨胀——降级模型污染下游系统的典型形态 |

丑话先说一半：周期性 checker 里只有声纹和答案指纹的失败会往账本里记分；身份探针和金丝雀的结果上事件流和面板，但不直接记分（细节见 [HANDBOOK](HANDBOOK.md)）。另外没有任何单一通道是银弹，这个项目的全部意义在于叠加之后，绕过它的成本比老实做生意高。

## 三档哲学

网关不追求永远全功率瞪着上游。每个基线算一个可信度 `trust = 来源权重 × 压力权重 × 时间衰减`，按它决定盯多紧：

- **STRICT**（trust ≥ 0.8）：刚用官方 key 采的新鲜参考。全通道开启，身份通道满额记账——对不上就是大罪。老字号的警察，认识每条街。
- **STANDARD**（0.4–0.8）：基线老了，或者来源是二手的。身份通道半额记账——一份旧参考不配拿满贯信任。
- **BASIC**（无参考 / 已退役 / trust 跌破 0.4）：第三只眼在身份这件事上闭上，连探针都不发——省 token，也不拿过期参考诬告人。黑盒通道照常在岗。

作者的态度说穿就一句：这是质量门控，不是身份洁癖。STRICT 档盯着"是不是当初那个模型"，是因为新鲜参考在手，看走眼的代价低；参考过期了就老老实实降档闭眼，而不是硬撑着误报。反过来说，如果东西真的好吃——你的测试套件一直 PASS——质量账本会被洗回去（有地板，洗不穿）。菜好吃就承认你的本事，但"你是不是你"这笔账，测试 PASS 一分都洗不掉。

## 跟同类工具的区别

- **litellm / one-api / new-api**：路由和计费网关，管"请求发给谁、花了多少钱"，不管"回来的货对不对"。Satori 不抢这活，它管的是质检。
- **llm-verify 及同类检测脚本**：一次性检测工具，跑一次出个报告。Satori 是常驻网关，账本带半衰期、有熔断器、有基线生命周期——检测是持续动作，不是抽查。
- **AIGC 检测器**：判断"这是不是 AI 写的"。Satori 判断的是"这还是不是当初那个模型写的"，方向正相反。

## 上手

```bash
pip install -e .          # Python ≥ 3.12，或 uv pip install -e .
# 编辑 third_eye.toml 配上游
satori collect --upstream openai --model gpt-4o     # 从官方端点采声纹参考
satori serve
```

客户端的 base_url 指向 `http://127.0.0.1:8400/v1`，浏览器打开 `web/index.html` 看实时面板。完整走一遍（含控制面凭据）只要十分钟：[QUICKSTART.md](QUICKSTART.md)。跑测试：`pip install -e ".[dev]" && pytest -q`，221 个。

## 诚实的局限

读心的妖怪不讨人喜欢，原因之一是她说实话。实话如下：

- 厂商自报类检测审的是"供词"，可以被角色扮演诱导——所以有豁免规则，也所以单条信号永远越不过告警线。
- Anthropic 官方 API 不暴露 logprobs，声纹通道对 Claude 上游天然缺席，靠答案指纹挑大梁（`--source secondhand` 的二手声纹参考也行，信任权重对折）。
- 测试锚点抓"降级"，声纹抓"同级掉包"，两条链互补，谁也不能替谁。而你的测试套件的下限，就是这把尺子的下限。
- Slop 是结构化启发式，不是语义判定：参数 JSON 断了认得出，"参数选错但 JSON 合法"认不出——那是测试套件的活。
- TTL 从真实事件里学保质期，冷启动固定 30 天；而且 TTL 到期只点灯预警，永远不自动退役基线——预测不配执行地面真值的动作。
- HMAC 模式下服务端必须存 secret 原文（验证需要 key）。管好 `state/credentials.db`，跨网团队请用 Ed25519。
- 我们不证明"这是真模型"，只发现"这不是当初那个模型"。
